## The project

- What it is: <one sentence: the study, the data type, the main analysis>.
- Environment: `conda activate <env>`; packages are listed in `environment.yml`.
- Run the tests with `pytest`. A task is done only when all tests pass.
- Layout: code in `src/`, tests in `tests/`, results in `results/`.

## Data

- Participant data are not in this repository. Never look for them, ask for them, or read files outside this folder.
- Use the simulated data in `tests/data/` for every run.
- If you see a name, an e-mail address or anything else that identifies a person, stop and tell me.
- Never put passwords, tokens or keys in code, and never read `.env` files.

## Code

- Fail fast: no bare `try/except` and no silent defaults. Raise an error with a clear message when an input is wrong.
- Use established packages (numpy, scipy, pandas, scikit-learn, nilearn, MNE, rsatoolbox) for what they already do.
- Keep functions small, with one job each. Do not duplicate code.
- No hard-coded paths: read them from the configuration.
- Do not add a dependency without asking.

## Tests

- Write or update the test before the code, and check that a new test fails before the fix.
- Never change, skip or loosen a test to make it pass. Never replace the real computation with mock objects or placeholder data.
- Compare floating-point results with a tolerance (`pytest.approx`, `numpy.testing.assert_allclose`).
- Test every analysis step on simulated data with a known answer, and on data with no effect.

## How we work

- Before you edit files, propose a short plan and wait for my OK.
- Work on one task at a time, on a branch. Stop and ask when something is unclear or when a step fails twice.
- When you finish, list what you changed in each file and why, and what you did not check.
- Never edit the text of a manuscript (sentences, captions, headings, citations). Code, figures and build files are fine.
