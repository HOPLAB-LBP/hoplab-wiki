# Review AI-written code

Review the changes as a careful colleague would, with the problems that AI agents often introduce in mind. Report what you find. Do not edit files unless the user asks.

## 1. Collect the changes

- Run `git status` and `git diff` (or `git diff <base>...HEAD` for a branch) and list the changed files.
- Read each changed file around every change, not only the diff lines.

## 2. Check the tests first

- Was any test edited, deleted or skipped, an assertion weakened or a tolerance raised? Each such change needs a reason the user agrees with.
- Do the tests check actual values, or only that something was returned or that no error was raised?
- Do the tests use mock objects, placeholder data or hard-coded outputs that bypass the real computation?
- Are floating-point values compared with a tolerance?
- Run the test suite and report the command and its result.

## 3. Check the code

- Silenced errors: bare `except:`, `except Exception: pass`, default values returned on failure.
- Leftovers of an earlier version: unused functions, old file names or paths, duplicated logic.
- Hard-coded paths, especially to data folders. Any read of participant data is a blocking problem.
- New dependencies, and whether an established package already does the job.
- Analysis choices the user did not ask for (filters, smoothing, thresholds, statistical tests, random seeds). List each one and ask whether it is intended.
- Docstrings, comments and names that do not match what the code does.
- Code that is more complex than the task needs.

## 4. Report

Give a table with file and line, the problem, what it can break, and a severity (blocking, should fix, minor). End with what you could not check. Do not state that the code is correct; say what the tests and the reading showed and what they did not.
